# 0.12.1 — Concurrent publication and exact Search repository identity

This maintenance release improves existing Core and Search behavior for applications
using the 0.12.0 release. Its primary benefits are correctness, failure handling and
qualification against the current contracts of the three consuming projects.

## Reliability fixes

- Pack/ref publication acquires database and catalogue locks in a consistent order.
  Catalogue SQL runs outside the catalogue read lock, avoiding a connection-pool
  wait that could block the writer needed to release the last connection (#445).
- Structured Search pages, cursors and counts distinguish exact repository names
  before database pagination, including databases whose ordinary comparison ignores
  case or trailing spaces. Projection deletion, rebuilding and indexing preserve
  neighboring repository identities (#463).
- A structured cursor closes its Hibernate session when transaction startup fails.
  Cursor cleanup preserves the original failure or cancellation and releases its
  ownership exactly once (#458, #473).

## Upgrade behavior

No production Flyway migration or default Search-profile change is introduced.
Existing valid 0.12.0 indexes retain their mapping when repository routing is absent.
A projection's repository identity is now immutable: assigning null or changing an
already assigned repository name is rejected. If database uniqueness semantics
collide with a different exact repository name, indexing reports the collision
instead of reusing or changing the other projection.

The additional structured SQL identity predicate supports H2, HSQLDB, PostgreSQL,
SQL Server and Oracle. Unknown dialects fail explicitly for those queries. The
query builder retains its existing repository-name trimming contract. Applications
owning custom aggregation queries must preserve exact identity independently.

See [paging and export](../operations/search-pagination-and-export.md) and
[routing and topology](../operations/search-routing-and-topology.md).

## Optional features and performance boundaries

Repository routing and the contention-aware publication selector are explicit
deployment options. The default remains unrouted Search and size-based publication.
Enabling routing, including a single routed shard, requires the documented offline
index rebuild. The double-buffered staging and bounded ranked-page experiments
remain benchmark/research work; this release does not activate them for consumers.

Retained measurements describe their recorded sources and workloads. They do not
establish an application-wide speedup from this version update, nor the cost of
the later exact-identity corrections. See the [performance decision record](../performance-status.md).

## Dependencies and qualification

The primary runtime selects JGit 7.8.1, Hibernate ORM 7.4.14.Final and Hibernate
Search 8.4.1.Final. The supported JGit matrix retains its existing older versions
and includes the current primary release. The normal API gate compares covered
library modules with 0.12.0, including Security, Smart HTTP, Spring Boot
Autoconfigure and Testcontainers.

The [real-consumer gate](../consumer-compatibility.md) uses immutable current
audio-analyzer, Taxonomy and sandbox revisions selecting 0.12.0, then substitutes
the isolated candidate into those same revisions. Consumers retain ownership of
their application dependency management and deployment support.

## Publication

The existing immutable public Maven repository, GitHub Release and server image
remain the normal distribution channels. The optional Maven Central profile can
prepare and verify a signed bundle; actual Central upload and publication require
production signing material and Portal credentials. A CI fixture-signed bundle is
not a published artifact. See [Maven Central publishing](../maven-central.md).
