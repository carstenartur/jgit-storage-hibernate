# Public Maven repository

Released artifacts are published to an anonymous static Maven repository maintained in the `maven-repository` branch of this public GitHub repository.

```text
https://raw.githubusercontent.com/carstenartur/jgit-storage-hibernate/maven-repository/
```

This avoids the authentication requirement of GitHub Packages and does not depend on Maven Central account availability. The repository is ordinary Maven layout generated by `maven-deploy-plugin`; Git only transports the resulting immutable files.

## Consumer configuration

```xml
<repositories>
  <repository>
    <id>jgit-storage-hibernate-public</id>
    <url>https://raw.githubusercontent.com/carstenartur/jgit-storage-hibernate/maven-repository/</url>
    <releases><enabled>true</enabled></releases>
    <snapshots><enabled>false</enabled></snapshots>
  </repository>
</repositories>
```

No username, token or Maven `settings.xml` server entry is required.

## Publication design

1. The release version is built and tested normally.
2. Maven deploys the parent POM and every module, including source and Javadoc JARs, to `target/public-maven-repository` through a file URL.
3. `prepare-public-repository.py` verifies the exact coordinate set, rejects snapshots and emits SHA-256/SHA-512 audit data.
4. A clean-room consumer resolves the parent and all public modules from the local staged repository using an empty Maven cache and no credentials.
5. The staged tree is merged into the dedicated `maven-repository` branch. Existing version directories may only be reused when every byte is identical.
6. The same clean-room consumer resolves the published files over anonymous HTTPS before the Git tag and GitHub Release are created.

The branch also contains `.nojekyll` and a small index, so it can be exposed through GitHub Pages later without changing Maven coordinates. The canonical URL deliberately uses `raw.githubusercontent.com`, because it works immediately for every public branch and requires no Pages account or site configuration.

## Snapshots

Development snapshots remain an optional authenticated GitHub Packages channel. They are not advertised as anonymously consumable releases.

## Failure policy

Release version directories are immutable. A retry may continue after a partially completed release only when the staged files are byte-identical to the already published version. Any difference aborts the release.
